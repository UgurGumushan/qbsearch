qbsearch 0.1.11 removes redundant Elitetorrent work, reduces Darklibria parser
CPU, and delivers UnionDHT's first completed page sooner. The release contains
all 58 standalone Python 3.9-compatible engines, icons, support files, and
installers for macOS, Linux, and Windows.
The website provides one direct ZIP download link and platform install commands.

## Changes

- Add nine provisional standalone engines: AniLiberty, FileMood, Internet Archive,
  Knaben, LinuxTracker, Torlock, TorrentClaw, TorrentFunk and UIndex. The ZIP now
  contains 58 engines and matching icons.
- Use a single API or listing response for seven of the additions, and bounded
  metadata requests for Archive and AniLiberty. Identical TorrentFunk and
  Torlock searches reuse disk caches for 15 minutes and one minute, respectively.
- Defer FOSS Torrents until its complete project-search request is verified.
  See the included NEW_PLUGINS.md for sources, tested request budgets and
  per-engine limits.

- The distribution page is static, with one direct Download ZIP link and
  installation instructions. The existing `/download/latest` URL redirects to
  the stable ZIP without a GitHub API lookup. The on-page catalog, decorative
  graphics, and marketing sections are removed; the plugin list remains in the
  repository documentation.
- Next.js is updated to 16.3.3 with the matching Bun lockfile.
- Elitetorrent reuses the initial search response for page one. The two saved
  captures retain identical result dictionaries with one fewer HTTP request.
- Darklibria appends DOM content and trims parser paths in place, retaining
  tuple snapshots and malformed/self-closing HTML behavior.
- UnionDHT emits each completed page in order and releases that page's result
  dictionaries while retaining cross-page deduplication.
- DMHY retains link attributes, emits the supplied magnet, preserves entities
  and metadata, and obeys the global result budget across pages.
- Maxitorrent requests consecutive POST pages, reads each row's size before
  resolving it, follows relative/quoted redirects, and retains external download
  hosts while bounding detail work and redirect cycles.
- Maintainers can run `bun run test -- --benchmark` to compare a checkout with
  a Git baseline. Reports include timing, CPU, memory, request and result counts,
  exact fixtures, and both source snapshots. `--matrix` varies concurrency and
  simulated response delays.

## Controlled measurements against 0.1.10

| Engine and workload                                                              |   Before |    After | Additional gain                                        |
| -------------------------------------------------------------------------------- | -------: | -------: | ------------------------------------------------------ |
| Darklibria wide DOM, zero delay, four workers: CPU                               | 175.9 ms |  62.8 ms | 64.3% less CPU; 2.80× faster                           |
| Elitetorrent one-result capture: HTTP fetches                                    |        3 |        2 | 33.3% fewer requests                                   |
| Elitetorrent two-result capture: HTTP fetches                                    |        4 |        3 | 25% fewer requests                                     |
| Elitetorrent one-result capture, one worker, simulated 100 ms responses: total   | 322.0 ms | 218.7 ms | 32.1% less elapsed time                                |
| UnionDHT five pages, one worker, simulated 100 ms responses: first usable result | 520.9 ms | 109.7 ms | 78.9% earlier output; total time essentially unchanged |

Measurements use two warmup pairs and 20 fresh timing pairs, with allocations
traced in separate processes. The Python 3.9 scheduling matrix preserves the
complete records in all 60 comparisons. Three initial zero-delay p95 flags
remain in the evidence; focused 100-pair repeats do not reproduce regressions
beyond the agreed limits. Five Python 3.11 comparisons also retain identical
records and pass the regression limits.

Darklibria's small-page control has no material gain, and its wide-DOM traced
peak allocations increase about 0.12 MiB. The AcademicTorrents prototype was
rejected: 94.5% lower traced allocations cost 51.3% more elapsed time. The
performance guide records the decision for every engine, including 15 deferred
changes that need usable functional evidence and 28 without a justified new
candidate. These measurements describe controlled workloads; live gains depend
on the remote service and query.

## Verification and service limits

- Local static checks, generated-file audits, standalone installability, and
  the website production build pass.
- Local suites on Python 3.9 and 3.11 each have 127 passing tests and five
  failures when this restricted environment attempts to bind HTTP test servers.
  Full strict checks on both versions are required in CI before publication.
- Focused local live checks for Elitetorrent (`inception`), Darklibria
  (`the hobbit`), and UnionDHT (`ubuntu`) could not connect after three attempts.
  Offline result equality does not establish current remote availability or
  verify live HTTP torrent downloads.
- The quality audit reports zero errors and three advisory loop warnings. Two
  new Darklibria warnings concern finite parser-list bounds the analyzer cannot
  infer; the Tokyo Toshokan warning was already present.
- Catalog health statuses remain based on recorded service evidence.

## Install or update

Download `qbsearch-0.1.11.zip` or `qbsearch-latest.zip` below, extract it, and
quit qBittorrent. From the extracted `qbsearch-0.1.11` directory, run:

| Platform           | Command                 |
| ------------------ | ----------------------- |
| macOS              | `sh install/macos.sh`   |
| Linux              | `sh install/linux.sh`   |
| Windows PowerShell | `.\install\windows.ps1` |

Reopen qBittorrent and enable the desired engines under **Search → Search
plugins**. The collection includes the Adult entries. See the included README,
installation guide, performance guide, and license provenance for details.
